# 滑らかな口復帰の保守資料

現在の仕様はv1.1.1（2026-10-26）。変更履歴は[CHANGELOG](../../CHANGELOG.md)を参照してください。

## 動作

- 発話中はSDKのAIUEOを使います。無音から80ms待機し、80msで元の表情に近い口へ変形してから、本来の口へ切り替えます。完全一致は求めず、舌・歯などは最後の切替で現れて構いません。
- 口の形や復帰先を確定できない条件では、無音から80ms後に瞬間切替します。タイミングの設定やInstant選択は設けません。
- 再発話・関連入力の変更・既存のLipSync停止設定を優先し、古い復帰形状を残しません。元口の表情遷移の完了までは監視しないため、遷移中に近似口と元口が一時的に一致しない場合があります。

## ビルド時の処理と入力保護

1. MA合成前、NDMFのビルド用コピーで復帰形状と自前Controllerを準備します。Scene上の導入物は既存の7シェイプ口と80ms待機の瞬間切替です。
2. MA合成後のFXから、実効Motion・Behaviour、レイヤー順序・ウェイトを使って復帰先を取り直し、自前の復帰レイヤーを置き換えます。
3. MAが変更した既存停止パラメータ名を引き継ぎ、後段のNDMF再処理でも変更が保持されるController参照を公開します。

元Body・元FX・共有Clip・シーン設定・Expression Parametersは編集しません。SDKのAIUEO/noneへ制御曲線を追加せず、インポート設定のRead/Writeも変更しません。既存の所有・Undo・共有アセット削除保護を維持します。

主な実装は[Editor/Generation](../../Editor/Generation/)、接続は[MururuMouthReturnPlugin.cs](../../Editor/Build/MururuMouthReturnPlugin.cs)、警告表示は[MururuMouthReturnWarning.cs](../../Editor/Build/MururuMouthReturnWarning.cs)です。

## 口の生成と対応範囲

- Body全体の標準fingerprint一致ではなく、その口を生成できるかで判定します。発音面・輪郭・UV・頂点対応・7シェイプ・口が使う骨とウェイトを検査し、口に無関係な改変だけで全体を拒否しません。
- 標準口、対応できる通常シェイプの組合せ、特殊口単独の0/100を対象とします。欠損・複数フレーム・非有限値等は口ごとに除外します。任意の独自シェイプ・口構造の生成を保証しません。
- defaultや輪郭を生成できなくても、独立した全ウェイトの開口・特殊口を生成できる場合は残します。中間的な組合せなど、欠損した形状を必要とする口だけを瞬間切替にします。
- 口の座標軸は自動補正しません。導入時の診断とBlenderでの補正は[FAQ](../website/docs/faq.md#body-axis)を参照してください。

## 復帰先の解析

- 元FXの既知の表情割当を読みます。Facial EXの復帰先入力は実際のEntry割当から取得し、設定画面の停止判定用パラメータと区別します。標準構成は17経路です。
- 左手・右手・Facial EX・Accessory・AFKは既知の状態・遷移表を確認します。右手が口を書き換える、割当が曖昧、未知の遷移がある等の条件は、その影響範囲で瞬間切替にします。任意のAnimatorを実行する解析器は設けません。
- 同期レイヤーはUnityの実効Motion・Behaviourと上書きを読みます。同期の存在だけで除外せず、未登録のMotionを元状態のMotionで推測補完しません。
- 一定のOverrideウェイトと定数口を合成します。可変ウェイト・未知の制御・メッシュ参照変更は影響成分を不確定とし、後段の明示的な完全書込で覆える場合は確定値を利用します。
- 未知の口シェイプはRendererの初期ウェイトも確認します。有効な未知シェイプは除外対象ですが、表情が明示的に0へ戻す場合や、口に影響しないシェイプは無関係な表情を止めません。
- AvatarMaskのTransformパス除外だけでは、SkinnedMeshRendererの口曲線が無効とは扱いません。Unity 2022.3の実Animatorで口の書込が残ることを確認しています。

## FaceEmo・MAの追加FX

- 最終FXの口を書き込む実状態を、同じ口成分の群へまとめます。ビルド用コピーの状態にSDK ParameterDriverを追加し、FX内のローカルIntで実際の群を参照します。ネットワーク同期項目は増やしません。
- FaceEmoの選択要求値だけでは、発話中の表情保留と実状態を区別できません。Driverはremote側でも各自の実状態を参照できるよう `localOnly=false` とします。未初期化では80ms切替にしますが、起動時の安全策だけでは恒久警告を出しません。
- 定数Clipと、口成分が等しいDirect以外のBlendTreeを利用します。Direct treeは正規化ONでも入力ウェイトによって口が変わるため、その口成分を不確定として扱います。
- WD OFFで口の指定が省略された状態は、先行する有効な全ウェイトOverrideが実際に書く成分だけを引き継ぎます。下位に書込みがなければ直前の口が残るため、不確定のままにします。初期Renderer値だけを根拠に確定しません。
- 「目を閉じる」「うっかり」は、下位FXが口を書く構成でそこへ戻ります。実FaceEmoの状態グラフとnative Animatorで、遷移中の補間と完了後の口を確認しています。
- 口を書かない制御・常時ウェイト0の層だけでは除外しません。SDKや他ツールが後段で制御を変える構成の包括保証はしません。

## 警告

対応できない条件はNDMFの警告として表示し、アップロードは継続できます。追加FXでは表情と理由ごとに集約し、組合せの全部か一部か、0.08秒後の瞬間切替、操作不要で使えることを日本語で案内します。

FaceEmoの表情を、確認していない手の割当と組み合わせて反復表示しません。通常の表情・ユーザーが付けた表情名・既知の内部制御状態を区別し、内部の数値表現や列挙名を理由にしません。

## 検証と負荷

- v1.1.1のEditMode検証は289/289成功（失敗・スキップ0）。実データを必要とするテストを含みます。再実行の条件は [TEST_ENVIRONMENT.md](TEST_ENVIRONMENT.md) を参照してください。
- native試験には、目のみ・部分的な口指定・下位の書込有無、Direct tree、同期・順序・ウェイト・マスクを含みます。実MA/NDMFビルドで最終復帰曲線、再処理後の保持、再ビルドの非累積、元入力不変を検証しています。
- 追加シェイプ・Animator評価の負荷はあり、実機CPU/GPU時間・FPSは未測定です。

テストの実行方法は[TEST_ENVIRONMENT.md](TEST_ENVIRONMENT.md)、試験コードは[Tests/Editor](../../Tests/Editor/)を参照してください。

## 配布

`LICENSE.txt` と `NOTICE.txt` を含むunitypackageをCIで生成し、GitHub Releasesへ公開します。BOOTHにはReleaseから取得した同じファイルをアップロードします。[リリース手順](RELEASE.md)を参照してください。VCC対応は公開とサイト切り替えの完了後に進めます。

Node.jsの共通処理がパッケージ内アセット・metaと元コミットを照合し、WindowsとLinuxの生成結果が一致した場合だけ公開します。`release-manifest.json` はCIの内部確認用で、BOOTHへの同梱は不要です。資料・Tests・Generatedはunitypackageに含めません。
