# 公開ファイルの管理

## 初期設定

Node.js 24以降とGitを用意し、各クローンのルートで実行します。追加のnpmパッケージは不要です。

```sh
node Tools~/privacy.mjs install
```

リポジトリ内だけに画像用clean filterと `pre-commit`・`pre-push` フックを設定します。既存設定が異なる場合は上書きせず停止します。cloneだけではGitのローカル設定は引き継がれないため、各環境で実行してください。

## 画像

自動処理する形式はPNG・WebPです。`git add` 時にXMP・EXIF・テキスト・日時・未知の付加チャンク・末尾の余剰データを除去します。圧縮された画素データは再圧縮しません。透過とアニメーションを維持します。

色表示に必要な情報と、内容を確認してSHA-256を登録したICCプロファイルは保持します。ICCの任意のプロファイル名は固定名に置き換えます。未知のICCプロファイル、破損画像、未対応形式は自動的に許可せず停止します。画像原稿は公開対象にしません。

clean filterはGitへ保存する内容だけを変え、手元の元画像は変更しません。手元の登録済み画像も除去したい場合は実行します。

```sh
node Tools~/privacy.mjs strip-images
```

## コミット・pushの検査

- `pre-commit` はステージされた全ファイルを読み、公開ファイル一覧・画像・テキスト・PDFを検査します。部分ステージの場合も作業ファイルで代用しません。Gitの作者・コミッターのメールも確認します。
- `pre-push` は送信する履歴の全コミットと各時点のファイルを検査します。最新の版だけから消しても、途中の版に残っていれば停止します。リモートの基点が手元にない場合は、fetchしてから再実行します。新規リモートには全履歴が検査されます。
- CIは送信済みの最新版を再検査する補助です。公開リモートへの漏えいを事前に防ぐ境界にはなりません。

手動確認:

```sh
node Tools~/privacy.mjs check-worktree
node Tools~/privacy.mjs check-staged
node --test Tools~/privacy.test.mjs
```

テキストでは個人のメール、ローカルのユーザーパス、VRChatのアカウント等のID、代表的な認証情報、内部資料の既知の見出し等を検出します。検出した値はエラーへ転載しません。GitHubのnoreplyメールは公開用として許可します。

任意の本名・住所・自由文の内部情報や、画像に写った情報を自動で完全判定するものではありません。フックは無効化できるため、利用環境の初期設定と変更内容のレビューも必要です。

## ファイルを追加・更新するとき

1. 公開してよい内容かを確認し、`Tools~/public-files.json` の `files` にパスを明示登録します。未登録の新規ファイルはコミット・pushできません。削除するときも一覧を更新します。
2. 非公開の資料・画像原稿・有料アセット・個人の環境設定・研究ログはリポジトリ外で管理します。禁止パスや未対応形式は、一覧へ追加しても検査に通りません。
3. PDFは本文・文書プロパティ・添付や注釈等を確認した後、そのファイルのSHA-256を `reviewedPdfs` に登録します。新規・更新PDFはhashが一致するまで停止します。hashを自動承認する機能は設けません。
4. 個人情報を含まないことを確認したICCを追加する場合だけ、`allowedIccProfiles` にプロファイル本体のSHA-256を登録します。
5. ポリシー・検査スクリプト・フックの変更もレビューします。公開済み作者名・商品名・URL・権利者表示は、検査で削除する対象と区別します。

sRGB ICCは内容を確認して登録しています。現在、公開対象のPDFはありません。

## 公開判断が完了するまでのpush保留

移行中のローカル環境では `git config --local publication.pushHold true` を設定します。`pre-push` がこの設定を確認し、送信前に停止します。ライセンス・配布方式・最終監査が完了し、公開の確認を得てから解除します。保留設定はローカル専用で、clone先には引き継がれません。

サイトの配信・IndexNow・監視は [WEBSITE.md](WEBSITE.md) を参照してください。

## 新しい公開用リポジトリを作るとき

既存の非公開Git履歴をpushせず、検査を通過した現行ファイルだけを新しい空のディレクトリへ書き出します。

```sh
node Tools~/privacy.mjs export dist~/public-source
```

出力先は未作成のディレクトリを指定します。`.git`・履歴・無視されたローカルファイルはコピーしません。書き出したディレクトリで `git init` と `node Tools~/privacy.mjs install` を実行し、公開用の作者設定を明示してから最初のコミットを作成します。ここで既存リポジトリをcloneして代用すると、古い履歴も引き継ぎます。
